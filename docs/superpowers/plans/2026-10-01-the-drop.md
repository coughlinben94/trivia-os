# The Drop Implementation Plan

> **For agentic workers:** execute task by task, test first. Steps use checkbox syntax.

**Goal:** New shiny question type `drop`: 4 tiles, each team splits 25 points across them on their phone (tap = +5, − takes 5 back, all 25 must be placed), one tile is correct and its points are the team's score. The TV reveals by dropping wrong tiles off one per Next press.

**Architecture:** Mirrors Choice (`choiceScoring.js`, `ChoiceBoard.jsx`, `ShinyChoiceQuestion.jsx`, `PHONE_MECHANICS` lock-then-score in `LiveMode.jsx`). Reveal is stepped like parts (`data.dropStep` 0..N, N = wrong tiles) inside `slideStepping.js`'s `computeNextStep`/`computePrevStep`, not the one-shot A-key reveal.

**Tech Stack:** React 18, Vite, Framer Motion 10, Supabase (`phone_answers.answer` is jsonb — no migration), vitest.

**Spec:** the 2026-10-01 design conversation (this doc is the spec + plan; Ben approved "go build").

## Global Constraints
- Data: `type:'question'`, `data.isShiny`, `data.shinyInputSchema.type === 'drop'`, `data.options [{id,label,image?}]` (4), `data.correctId`, `data.dropTotal` (default 25).
- Phone answer row: `answer = { [optionId]: wholeNumber }`, must sum to `dropTotal`, none negative.
- Slide state: `dropLocked`, `dropLockedAt`, `dropStep` (0..N), `dropRevealed` (true once step == N), `dropResults` `{ totals:{id:n}, allIn:n, teams:n }` written at score time.
- Drop order = seeded shuffle (`dropSeed`, stamped at first lock, cleared on Unlock) of the wrong tiles; never the correct one.
- Phone: tap +5, − takes 5 back, per-tile "All in" (whole pool on one tile). No per-tile minimum.
- TV shows `dropResults.totals` (what the room put on each tile) on the tiles from the lock on.
- TV: GPU-only animation (transform/opacity), reduced-motion guard, fonts from `theme.fonts.*`, easings from `lib/easings.js`. TV never shows per-team splits, only aggregate `dropResults`.
- Never push; branch `feat/the-drop`.
