Ambient Surge — "ambient but lively," Halloween round-boundary concept

Not a cinematic journey. The persistent ambient theme never stops or re-mounts — a round boundary just spikes the SAME anchor/drifter/atmosphere layers it already has, hard, for ~3s, then decays back to the normal loop. Zero new mechanism, zero canvas/rAF, zero new engine. Every value below is a real Halloween theme color (client/src/themes/index.js) and a real keyframe shape from ParticleBackground.jsx's HalloweenAmbient — the surge keyframes are the SAME shapes, just re-tuned faster/hotter, matching round-journeys.md's own documented lesson (the galaxy "hyperspace snap" beat did the identical trick by spiking the existing star-warp value for one beat instead of building a new one).

What this demonstrates

Press Trigger Round-Boundary Surge. Over ~3.2s: the jack-o-lantern anchor flares hot-white then settles (hwFlare, a brightness/saturate spike on the exact same anchor element — no new node), a soft radial flash washes once, the three bats scatter hard outward from their wander loops and flap faster, the fog banks switch from a slow ~50-70s drift to a ~4s rush, and a one-shot burst of embers streams up from the anchor. Everything then eases back into the ordinary ambient loop — the theme never stopped, paused, or re-mounted; nothing outside the safe-area's normal footprint appears. This is round-boundary "liveliness" bought for the cost of a CSS class toggle plus one small ember array, not a bespoke 40-second canvas sequence.

What deliberately did NOT change

The base sky gradient, ground silhouette, headstones, and the anchor's resting glow are byte-identical to the shipped HalloweenAmbient in ParticleBackground.jsx. The surge is additive state on top of the real theme, not a redesign of it — this is the whole point: the ambient theme system already passed its acceptance gate once; a surge state shouldn't need to re-earn it.

How this would actually wire in

A round boundary already fires a single Supabase write (per useShow.js — no client-side timers drive show state). ParticleBackground.jsx would read a short-lived surging prop (or a `show.showState` flag cleared after ~3s, mirroring how scoreboardVisible/answer_reveal already work) and toggle one class on its root wrapper. Every bespoke theme gets its OWN surge recipe (this is a per-theme creative decision, same as the anchor/drifter/atmosphere design itself was) — Sonora Balloons' surge might be a burner-flare + brief upward lift on all 5 balloons; Autumn Harvest's might be a hearth flare + a burst of embers. The mechanism (toggle a class, spike existing keyframes, decay back) is what's reusable across all 9 bespoke themes — the recipe inside it is not.

Self-gate (adapted from the ambient Acceptance Gate — this is a state ADDED to an already-gated theme, not a new theme):
  • ✓ Anchor stays the same named element (jack-o-lantern) through the surge — no new anchor introduced
  • ✓ Drifters (bats, fog) keep real translate motion — surge only changes speed/amplitude, not the motion type
  • ✓ Safe-area respected — surge intensity is highest at the anchor (top-right, already outside the box) and along the edges; nothing peaks inside the center 60%×45%
  • ✓ In-family color — flare/flash/embers reuse the theme's own highlight (#e0c0f8) and moonGlow (#9a5fd0), no new hues introduced
  • ✓ GPU-only — every animated property here is transform/opacity/filter(brightness,saturate); filter is animated here (brightness spike), which the ambient law explicitly allows to be STATIC but not animated — flagged below, needs Ben's call
  • ✓ Reduced-motion — the .hw-anim guard already covers every animated element in this mockup; toggle the checkbox above to verify the surge silently no-ops (anchor and fog stay static, bats freeze) instead of jump-cutting
One honest flag, not swept under the rug: hwFlare animates filter: brightness(), and ambient-design-law.md's GPU rule is explicit that filter may be STATIC but never ANIMATED. This mockup breaks that rule on purpose to test whether the flare reads well — if Ben likes the effect, the real implementation needs a compliant substitute (e.g. animate a screen-space white overlay's opacity instead of filter brightness, which produces a similar "flash" perceptually via compositing rather than a filter animation) before it ships.
