Why this file exists

New ambient theme, working name "Campfire Sing-Along," built from a locked Recraft vector+raster pair (night lakeshore, two empty camp chairs, purple sky, dark treeline, fire reflection on the lake, sandy foreground with a winding path). Per concepts/OBJECT-RENDERING-PROTOCOL.md's noun test, the treeline/chairs/fire/logs/sand/reflection are all figurative-by-contour elements — but the noun test's escalation ("generate it") is already satisfied upstream: these paths are lifted directly from the locked, already-generated Recraft vector, not hand-typed from scratch. No new figurative geometry was invented in this file.

Reconciling the source composition with the safe-area rule

The Recraft source's own internal layout puts the fire/chairs roughly mid-frame (flame tip at 70.6% of the source's own height, chairs from ~74-97%) — which would sit squarely inside references/themes.md's hard 20-80%/28-72% question safe-area if used at native scale. Rather than hand-editing any traced path's coordinates (which would break "the vector is the geometry source of truth"), the entire traced assembly is displayed as one uniformly-compressed block (a single CSS width:100%; height:86.87% on the wrapping <svg>, bottom-anchored, native viewBox unchanged) so every path's relative position to every other path is preserved exactly, and only the assembly's placement within the stage changes. A first attempt used the opposite construction (an oversized, cropped box) on the theory it would push content down the same way — rendering it showed the reflection-dimming scrim landing on a completely different part of the frame than the actual (still bright) reflection, which is what caught the direction error. See concepts/campfire-sing-along-spec.md for the full derivation, the wrong-direction first pass, and the resulting per-element stage-percent bounds.

Reflection streak vs. the safe-area — the specific rule this brief called out

After the remap, the reflection streak spans stage-y ≈67.34%-73.94% — meaning essentially its entire visible extent falls inside or right at the edge of the y28-72% safe-area, and its x-span (≈32.3-70.1%) sits fully inside the x20-80% band too. Two things address this, not one: (1) the source's own reflection shape is already a scalloped/broken silhouette (a row of connected lens-shaped humps, not a solid bar) — so "broken up" was true before any edit; (2) #reflectionScrim is a dark radial-gradient overlay sized so its real (non-decayed) alpha actually spans the reflection's own bounding box, not just its dead center.

Correction, 2026-07-27: the first version of this scrim shipped with a real, measured bug, not just a documented risk — two independent design-critic passes pixel-sampled the actual rendered PNG and found no measurable brightness differential between the reflection inside vs. outside the zone (peak pixel ~247-249/255 either way). Direct re-sampling confirmed why: that version's ellipse radius (Ry ≈4.2% of stage height) decayed to near-zero alpha before reaching most of the reflection's real 6.6%-tall extent — the bottom ~1.4% of the streak sat entirely past the gradient's 100% stop, untouched by construction. Fixed by widening the box/ellipse so its radius (Rx≈27%, Ry≈4.7% of stage) actually covers the reflection's real half-extents, and adding a third gradient stop (0%/50%/70%/100%) so alpha stays ≥0.35 out to 70% of the radius instead of crashing to near-zero by the midpoint. Re-rendered and re-sampled the same regions after the fix — see concepts/DESIGN-WORKER-LESSONS.md's corresponding entry for the numbers. A first attempt (before either of these) used a rectangular box with a straight top-to-bottom fade and left a visible hard seam partway down the streak (the "banded rectangle" pattern themes.md warns about) — that's why this stays a padded radial shape, not a box fade. Everything else the source draws in that vertical range (treeline, sand, chair silhouettes) is dark/low-contrast atmosphere already and needed no separate treatment, per themes.md's "atmosphere may pass behind the text freely" allowance.

Radial-gradient margin math — done in the spec file, not eyeballed

Given this exact project's most recent documented failure (concepts/DESIGN-WORKER-LESSONS.md's 2026-07-26 entry: an earlier Campfire flame build shipped with two of three glow gradients overrunning their own box before reaching transparent, plus a box-shadow glow on a non-rounded div), every radial-gradient layer here (#flameGlow, #flameCore, #groundPool) has its own box and its center ± radius computed per-axis against that box's own width/height in concepts/campfire-sing-along-spec.md, with real margin on every side except the ground-anchored bottom edge (sanctioned per the Established Convention — an anchor's own base is allowed to run to/past its box edge). No box-shadow is used anywhere in this file for a glow effect.

What's static vs. animated

Static (traced, unedited path data): treeline, reflection base shape, sand path, sand ground, fire-lit sand halo, both chairs, the log base, the flame silhouette itself. Animated (hand-authored, GPU-only transform/opacity): flame flicker (the isolated flame silhouette scales/fades on an irregular 2.6s cycle — pulled out of the merged traced group into its own small SVG specifically so it alone can flicker without the treeline/chairs flickering with it), ambient bloom + hot near-white core pulsing in the same rhythm, a ground-anchored light pool pulsing on a deliberate phase delay (animation-delay:.55s) so it visibly lags the flame instead of strobing in sync (the Established Convention already confirmed-good for this project's fire pattern), 7 rising embers (the drifter) on staggered 4.5-7.5s cycles with negative animation-delays so none pop in synchronized, 22 twinkling stars (irregular 3.2-6.6s cycles, same negative-delay treatment), and one shooting star every 34s.

A unit bug the first render caught

Embers and the shooting star were first written with vh/vw translate distances — relative to the browser viewport, not this file's .stage box (a capped min(1200px,92vw) container, not the full window). The first render showed embers rocketing well above the treeline into the star field instead of the intended modest near-fire drift. Fixed the same way firefly-summer-pond-deck-v1.html handles the identical class of bug: added container-type:size to .stage and switched both keyframes to cqh/cqw (container query units, resolved against the stage's own box regardless of the surrounding page or viewport size).

Hero beat — deliberately not built

themes.md's Recipe permits an optional ~3-6s heightened moment every few minutes. Not attempted here: this is a first-pass prototype and every hero-beat gate (shipped-state-without-it, zero new elements, peak-state safe-area re-check, decoupled timer) is real overhead better spent once the baseline itself is confirmed to read correctly.
